# V6.6.8 DURABLE AUTH STORAGE — Psycopg 3, version-gated by interpreter.
#
# History: `psycopg[binary]==3.2.3` stalled the Render build. That release
# publishes linux wheels for cp38-cp313 only; with no runtime pin in this repo
# the platform default is used, pip fell back to a source build needing libpq
# headers, and the deploy failed (Render then keeps the previous build serving,
# which is exactly what was observed).
#
# psycopg-binary 3.3.5 adds cp314 but DROPS cp39, and psycopg 3.3.x requires
# Python >= 3.10. Neither range alone is safe on an unknown interpreter, so the
# requirement is gated by environment marker and resolves correctly on any of
# them. This cannot repeat the previous failure regardless of what Render runs.
#
#   python >= 3.10  -> 3.3.5+  (linux wheels cp310-cp314)
#   python <  3.10  -> 3.2.x   (linux wheels cp38-cp313)
psycopg[binary]>=3.3.5,<4; python_version >= "3.10"
psycopg[binary]>=3.2,<3.3; python_version < "3.10"
